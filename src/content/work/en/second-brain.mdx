## The Context

Every AI conversation started from zero. I had to re-explain who I am, my projects, my skills, my CV — context scattered across files, never up to date, and no AI has a durable memory I control. I wanted my knowledge base to be **reachable by any AI** (ChatGPT, Claude, Cursor, opencode), not locked in one tool.

## What I Built

A self-hosted "second brain": an **Obsidian vault** as the source of truth, versioned on a **private GitHub repo**, indexed by an **n8n** pipeline into **Qdrant** (vector store), embedded locally with **Ollama bge-m3**, and generated with **DeepSeek V4 Flash Vision** (via the OpenCode Go gateway). Everything is exposed to any AI through a **dedicated MCP server**, authenticated with **OAuth**.

**Three MCP tools:**

<CardGrid>
  <Card title="second_brain_ask">
    RAG over my whole knowledge base: any AI asks a question, gets a sourced answer (projects, stack, CV, lessons learned).
  </Card>
  <Card title="second_brain_add">
    Any AI can write notes. Each note is auto-classified (type, tags, folder), checked against duplicates, and held in quarantine until I validate.
  </Card>
  <Card title="second_brain_project_details">
    The AI dives into a project's <strong>source</strong> (README or a specific GitHub file) on demand — without bloating the vault.
  </Card>
  <Card title="Differential ingestion (every 30 min)">
    Private repo → deterministic-ID chunking → only new or changed chunks are embedded (~2 s in steady state). Idempotent, loss-free.
  </Card>
  <Card title="Housekeeping (weekly)">
    A report flags redundant note pairs (semantic similarity), written in quarantine for me to review.
  </Card>
</CardGrid>

## What This Experience Taught Me

Shipping a production MCP server surfaced several hard-won lessons: **OpenAI model nodes don't expose custom headers** (the OpenCode Go gateway requires `x-opencode-session`) → call the API directly over HTTP; **splitInBatches aborts on empty items** → prefer linear pipelines; **uncontrolled AI writes are a real threat** → the quarantine-by-status pattern is the simplest effective gate; and **re-indexing is not idempotent by default** → deterministic IDs (content hash) make ingestion duplicate-free, differential and near-instant.
